# Clarifications fixed before the pilot

The original METHODOLOGY.md remains unchanged, with its original SHA-256 in environment.preparation.json. These refinements resolve the independent method review before any pilot measurement.

- Primary peak RSS is the resource high-water mark immediately after query materialization and before correctness digest computation. It includes interpreter/library imports, input loading, backend preparation and warm priming. The end-of-worker peak is recorded separately. RSS is neither incremental query allocation nor physical memory uniquely owned by this process.
- Expected digests are generated once outside measurement workers by a NumPy oracle. Small hand-calculated fixtures independently test every backend and the oracle. Digesting is streamed to avoid large validation structures.
- Warm priming results are deleted, followed by gc.collect(), before starting the measured query. Prepared inputs remain alive. Source arrays are retained for all three backends.
- Python uses ordinary lists of rows and a customer dictionary. pandas uses int64 DataFrames backed by the canonical arrays where possible. SQLite uses an in-memory database, customer primary key, no fact indexes, threads=1 and temp_store=MEMORY. Inserts use 10,000-row conversion chunks. These are concrete implementations, not claims about each language's optimal performance.
- NumPy is imported in all workers for the shared NPZ loader. pandas is imported only in pandas workers. Imports occur before cold timing but contribute to peak RSS. Peak RSS therefore includes different backend library overheads.
- The cumulative worker budget is 900 seconds across pilot and main, counting parent-observed elapsed worker time, including startup, failed workers and timeouts. Campaign deadline is 1,200 seconds from the first pilot start through main completion. Each worker timeout is at most 30 seconds or the remaining budget/deadline. A one-second pause separates randomized blocks. Only task-owned children may be terminated by timeout.
- Read-only vm_stat swapout counters are checked before and after each trial; any increase relative to that phase's baseline stops the phase. This is a system-level precaution and cannot attribute swap activity to the benchmark. The 2 GiB RSS threshold is checked after a worker completes. It is not a live hard memory cap.
- Data and order seeds are distinct. Main uses order seed 73129, pilot uses 73130. Independent dimension RNG seed is data seed + 1. Fact datasets at different sizes are deterministic but are not guaranteed nested samples because array draws consume RNG state in size-dependent blocks.
- Safe thermal telemetry via pmset -g therm is unavailable in this execution context. Temperature, thermal throttling and per-query energy are not observed. Power source output was ambiguous (AC Power together with a discharging battery), so no stable power-mode claim will be made.
- The proposed plotting-package install into the isolated project environment failed because external package-network resolution was unavailable. No plotting packages were installed. Charts use the already installed ReportLab and macOS sips for PNG export. The virtual environment inherits installed NumPy/pandas from the verified runtime.

The synthetic input has no nulls, strings, repeated dimension keys or skewed distribution model. JOIN means inner join followed by aggregation. File parsing formats, other data types, disk databases, multithreaded execution and environmental impact are outside scope.
